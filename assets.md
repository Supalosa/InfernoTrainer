# Cache assets

This trainer owns the cache assets needed by its encounter. The SDK contributes
the shared player equipment, animations, combat effects, and sounds used by SDK
content.

## Project layout

- [`src/assets.ts`](src/assets.ts) names the trainer's NPCs, animations, regions,
  models, spot animations, items, objects, and sounds. Gameplay imports IDs from
  this module.
- [`osrs-assets.config.ts`](osrs-assets.config.ts) selects the OpenRS2 cache,
  output directory, scene adjustments, and optional extraction hooks.
- `public/osrs-assets` is generated by `npm run assets` and ignored by Git.
- Webpack copies that directory to `dist/osrs-assets` with the application.

## Local setup

Use Node 20. Keep the three repositories as sibling directories:

```text
workspace/
├── your-trainer/
├── osrs-sdk/
└── osrscachereader/
```

Install matching SDK and asset-tool versions in a new trainer:

```sh
npm install --save-exact osrs-sdk@<version>
npm install --save-dev --save-exact osrs-sdk-assets@<same-version>
```

The asset command checks that these versions match so the manifest schema and
extractor stay in sync.

Install the reader and trainer dependencies, then generate and serve the assets:

```sh
cd ../osrscachereader
npm ci

cd ../your-trainer
npm ci
npm run assets
npm run start
```

The asset tool defaults to `../osrscachereader`. Use
`OSRS_CACHE_READER_PATH=/path/to/osrscachereader npm run assets` when the checkout
is elsewhere. The first build downloads the pinned OpenRS2 cache and XTEA keys to
`.cache-render/openrs2`; later builds reuse them.

## Adding encounter content

Add each asset to `src/assets.ts` and use that exported constant in gameplay:

```ts
import type { CacheAssets } from "osrs-sdk/asset-manifest";

export const MY_BOSS_ASSETS = {
  npcs: {
    boss: {
      id: 12345,
      animations: {
        attack: 6789,
        death: 6790,
      },
    },
  },
  regions: {
    arena: { id: 4321 },
  },
  spotAnims: {
    projectile: { id: 987 },
  },
  sounds: {
    bossAttack: { id: 654 },
  },
} as const satisfies CacheAssets;
```

NPC standing and walking animations come from the NPC definition. Declare other
animations that gameplay requests. Sounds referenced by extracted animation
sequences are included automatically; declare sounds played directly by gameplay.

Run `npm run assets` after changing requirements. Missing definitions fail the
build with their cache ID, making cache-version mistakes visible before deployment.

## Hosting

The trainer loads `osrs-assets/manifest.json` from its own origin by default.
Deploy the complete `dist` directory so the manifest, hashed model payloads, and
sound pack remain together.

To host the generated asset directory separately, serve it as static files and
set the manifest URL while building the trainer:

```sh
OSRS_CACHE_RENDER_MANIFEST_URL=https://assets.example.com/my-trainer/manifest.json npm run build
```

The asset host must allow cross-origin requests. Serve `manifest.json` with
revalidation and the hashed `.bin` and `.soundpack` files with immutable caching.

Cache-derived assets are separate from application images and imported audio.
All RuneScape assets are property of Jagex.
